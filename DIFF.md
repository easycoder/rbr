# What to do

- **Restart Scenario Studio** to load the changed `studio.allspeak` shell.
- **Redeploy the controller.** This release stops duplicate `room.state` rows, adds journal retention (1 GiB and 10% of current free space, whichever is smaller) and adds `journal-export.py`. Existing journal files keep their old duplicates; the converter collapses them.
- **Install the daily export timer** by re-running `rbr-setup.sh` (Step 6e), or create `rbr-journal-export.service`/`.timer` from the repository. It runs at 03:30 and writes one bundle per day under `<journal-root>/exports/`; the newest 14 are kept. A manual run is `python3 journal-export.py --day YYYY-MM-DD`.
- **To change the limits**, write one-line files in the controller's working directory: `journal-max-bytes` (for example `1G`, `512M` or `0` to disable) and/or `journal-max-free-percent` (for example `5`, or `0` to disable).
- **Re-import after restarting the Studio.** The old `Journal 2026-11-06 14:00-19:00` (and any 16:00–20:00 attempt) is baseline-only because the importer reused a cached bundle from 11:07–12:54. Delete those scenarios (the new confirmation popup) and import again; root/SSH imports now pull the current controller day on every attempt.
- **Try the importer and converter** from `tools/scenario-studio`, or use the Studio's new **Import journal…** button. The button accepts a bundle, a raw `.jsonl`, a local journal root, `user@host` (using `/data/rbr-heating/events`), or `user@host:/journal-root`, asks for an optional day and window, and adds the result to the **Journal** group. It uses the operating system's SSH client and key; do not add SSH secrets to the controller's `credentials` file.
- **CLI equivalent**: `python3 journal_import.py --source /data/rbr-heating/events --day 2026-11-06 --dest fixtures/local/journal/qed6-2026-11-06`, then `python3 journal_to_scenario.py --bundle fixtures/local/journal/qed6-2026-11-06 --from 07:00 --to 09:30 --out fixtures/local/scenarios/journal/kitchen-morning.json`.

- **On the same network**, use `--ssh linaro@<controller> --ssh-root /data/rbr-heating/events` instead of `--source`. No controller-side change is needed; the importer runs only `cat` on known paths.
- **No new Python packages.** Both tools use the standard library. If a bundle has no base map, pass `--map` to the converter.

# What changed

- **Stale bundle cache fixed.** `journal_ingest.py` reused `fixtures/local/journal/<day>` whenever it existed (`if bundle.exists(): pass`), so a second **Import journal** returned the first download even though the controller had moved on. Root and SSH imports now always refresh the bundle with `--force`; an explicit bundle source is still read as-is. This is why the controller was logging seq 1739 at 19:29 while the Studio reported a range ending at 12:54.
- **Empty journal windows are rejected.** `journal_to_scenario.py` now checks that the requested window contains events and that they produce actual changes. It used to seed the pre-window state and return that baseline when the window was empty; the 14:00–19:00 import produced only 16 baseline rows because the imported journal ended at 12:54. The error now names the requested window and the journal's real range. The Studio shows that error instead of adding a useless scenario.
- **Event times are visible.** The Steps table now displays `HH:MM:SS` rather than a truncated ISO date; the full timestamp remains in the inspector.
- **Daily export.** `journal-export.py` reads a day, drops repeated sensor readings that did not change temperature/humidity/battery, copies the maps the kept events reference, and writes `<journal-root>/exports/<system>-<day>.tar.gz` in the same bundle format the Studio importer accepts. `--mode full` keeps everything, `--mode summary` drops sensors; `--keep` retains 14 archives by default. `rbr-journal-export.timer` runs it daily at 03:30; `rbr-setup.sh` installs it.
- **Journal retention.** `eventlog.py` prunes before and after each flush. It deletes the oldest day files until the journal is under the smaller of the absolute cap and the free-space share, then deletes maps no remaining day references. The day just written is always kept; if it alone exceeds the cap it is kept with a warning. Defaults are 1 GiB and 10% of current free space.
- **Duplicate room-state fix.** `JournalRoomState` and `JournalSensor` now compare a hash of the serialised record. Before this, AllSpeak normalised the stored JSON-looking string differently from the freshly built one, so every cycle looked changed: the live 25-minute sample held 3,350 `room.state` rows, about 376 identical repeats per room. The same day should now be roughly one state per room per minute.
- **Bundle.** `tools/scenario-studio/journal_bundle.py` defines the manifest, `events/YYYY/MM/YYYY-MM-DD.jsonl`, `maps/<hash>.json`, archive writing and safe extraction.
- **Importer.** `journal_import.py` pulls one day and every referenced map from a local directory or over SSH, writes a bundle and optionally a `.tar.gz`.
- **Converter.** `journal_to_scenario.py` reads a bundle or a raw day plus `--map`, selects the latest map at or before the window, seeds the pre-window state, drops unchanged readings and duplicate states, and emits controller steps and visible expectations. It records UI requests as warnings rather than replaying gestures it cannot see. Expectations use the page's real formatting: temperatures truncate to one decimal (`1939` is `19.3`, not `19.4`) and Advance is read from the collapsed row's subline `(A)` marker, because the button is only painted when the row is expanded. The live sample converts to 49 steps; the live-map run passed all 45 steps in 20 seconds.
- **Studio shell.** **Import journal…** runs `journal_ingest.py`, which chains import, conversion and `scenario_library.add`, then selects and loads the generated scenario. A bare `user@host` now means that host with the standard `/data/rbr-heating/events` root; before, it was treated as a local path and produced a `No such file or directory` error. The SSH importer now builds `ssh <host> cat <path>` in the right order; the previous version swapped host and root, so the error named `/data/rbr-heating/events` as the unresolvable host. Use `user@host:/other/root` if the journal is under `heating-data/events` rather than the default. The shell smoke test still passes with the new controls.
- **Demo end pause.** `scenario_runner` has `--end-pause-ms`; **Demo** passes 5000, so the final screen stays visible for five seconds before the headed browser closes. The delay is inside the runner's `finally`, and is skipped if no browser started. Normal runs remain immediate.
- **Multi-row selection and deletion.** The Steps table uses AllSpeak's native `set selection of Steps to multiple`; Ctrl/Shift-click or drag selects several rows, and **Delete rows** confirms before removing them from a library scenario. Public examples must be duplicated first. The earlier click-toggle workaround and its request entry are gone.
- **Scenario editing tools (first pass).** The right-hand Inspector now has **Duplicate…** and **Rename…**. Duplicate names and copies a scenario and its brief into the library; Rename changes a library scenario's display name and index entry. Public examples cannot be renamed in place; duplicate one first. Row insertion/deletion and cell editing are the next pass.
- **Studio settings persist.** Window position/size, last group and scenario, SSH source, journal day and time range are written to `fixtures/local/studio-settings.json` from the `on close` handler and restored on the next start. A deleted group or scenario falls back to All and the seeded Advance example. The file is machine-local and ignored by git.
- **Quit button.** A **Quit** button in the top toolbar closes the window; because it closes rather than calling `exit`, the same settings save runs.
- **New scenario chooses its group.** Clicking **New scenario** now asks which group should own the draft, defaulting to the currently selected library group (or `Unsorted` from All/Local). Draft passes that group to `ai-draft.py`; a new group is created through the normal library path and added to the selector. This removes the old behaviour where New from `Examples`/`Local` silently fell back to `Unsorted`.
- **Examples are real scenarios.** The three public examples are seeded into the local **Examples** group on first start by `scenario_library.py seed-examples`. They are ordinary deletable library copies; the public files remain in `docs/examples` for the README and tests. `fixtures/local/.examples-seeded` stops deleted examples returning; remove it or run `seed-examples --force` to restore them. `Local system` remains a generated, read-only snapshot. The hard-coded example rows are gone from `BuildScenarioList`, and the fallback after deleting a library scenario now uses the seeded Advance copy when it exists.
- **Delete confirmation.** **Delete scenario** now opens a modal confirmation naming the scenario. The old two-click arming message in the bottom panel is gone; Cancel leaves the scenario untouched, and only the confirmed path starts the move to `.trash`. The shell test cancels the dialog and checks the scenario is still listed.
- **Delete button.** Delete is keyed to the selected library entry's **name** as well as its path: `LoadLibrary` records every entry in `LibraryNames`, `ScenarioPicked` remembers `SelectedName`, and `SetDeleteButton` enables Delete when the selected name is a library entry and the file exists. It falls back to the local-library path prefix and then `LibraryPaths`. Before, it relied only on `LibraryPaths`, which is rebuilt by the group filter and refresh, so a valid selected library scenario could look undeletable.
- **Docs and tests.** Scenario Studio README, `doc/EVENT-JOURNAL.md`, `doc/CONTROLLER-FILES.md` and `AGENTS.md` describe the tools and limits; `eventlog_test.py` covers retention and `journal_check.py` covers import, bundles and conversion.
