| 2026-10-19 | AllSpeak language / JS runtime pin | Add `loop` with explicit forms: counted (`loop from 0 to Count - 1 as N`) for variable arrays and parallel arrays; ordered list/JSON array (`loop over List as Item`, optional `as Index, Item`); dictionary (`loop over Dict as Key` or `as Key, Value`); properties (`loop over properties of Obj as Name, Value`). Define copy vs alias, iteration order, termination bound (snapshot/captured at entry), snapshot vs live mutation, and loop-variable scope. Confirm the upstream spelling: the public `09-control-flow.md` fetched 2026-10-20 still documents only `while` and label-driven loops, and the pinned `?v=26051101` lacks `loop`. Keep Python/JS parity, then pin the JS build. | `while` + counter; `item`/`element`; dictionaries have no generic iteration today. | Open |
| 2026-10-19 | AllSpeak syntax | Define the `loop` body as the existing `begin ... end` block; multiple commands sit inside and `end` closes it. Do not introduce `end loop`. | 2026-10-19 | AllSpeak JS runtime pin | `on failure` should continue after its clause, as upstream does; the pinned build stops the thread. | `rest get ... or begin ... go to ... end`. | Open (not yet needed in the UI) |

| 2026-10-24 | AllSpeak JS runtime | Give a parked `send … and assign reply` its own reply slot instead of one `replyVar` / `replyResume` per program. Today any second blocking send from the same program (here: an MQTT map push landing while a sheet module's open-message is parked on its reply) overwrites the slot; the first sender's reply then finds it empty and is silently dropped, and the first sender stays parked for ever. Per-send (nested) slots, or a clear runtime error when a second send would overwrite a parked one, would make the failure loud at worst. | `shell.allspeak` holds a map that arrives while a sheet editor is open (`PendingMap`), refuses to apply it there, and flushes it after the module's reply lands (`FlushPendingMap`), so the second send never starts while the slot is held. `tests/pwa-schedule-save-check.js` guards the workaround. | Open |
| 2026-11-03 | AllSpeak Python | `send email` should support attachments (at least one file, with a filename and MIME type). | The controller emails nothing itself: `rbr-backup.py` uses Python's `smtplib`/`email.message` so it can attach the ZIP. The existing `send email` command remains fine for the registration and recovery bodies. | Open |
| 2026-11-07 | AllSpeak Python graphics | Give `logpane` a maximum line count, e.g. `create Log maxlines 2000` or `set the maximum lines of Log to 2000`, so an append-only log can discard its oldest lines without shell code and without losing per-line colour. | RBR Studio's `TrimStepsLog` reads `the text of Log` every hundred ticks (about a second), splits it, and rewrites the newest 2000 lines with `set the text of Log`; a trim loses the lines' colours. `studio.allspeak` uses it for the Steps tab. | Open |
